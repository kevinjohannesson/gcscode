# One-command dev stack — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pnpm dev:sitl` starts SITL with MAVProxy and mavlink2rest, MediaMTX and gcscode's dev server, prints "ready to fly" once the vehicle can arm, and one Ctrl-C stops everything it started.

**Architecture:** One dependency-free Node file, `scripts/dev-stack.mjs`. It exports a service table and `runStack()`, which checks ports, starts each service in its own process group, prefixes their output, waits for each to come up, then polls mavlink2rest until the vehicle is ready to fly. When run as a script, it calls `runStack()` with the real table. The tests call `runStack()` in a child Node process with stub services, so they never start SITL, MediaMTX or Vite.

**Tech stack:** Node built-ins only (`node:child_process`, `node:net`, `node:dgram`, `fetch`), `node:test`, bash for `run_sitl.sh`.

**Spec:** [`docs/specs/2026-11-10-dev-stack.md`](../specs/2026-11-10-dev-stack.md), § The launcher and § Delivery 2. Read it first. This plan argues from it and does not repeat its reasons.

## Global constraints

- **One file, no dependencies.** `scripts/dev-stack.mjs`, plain ESM, Node built-ins only. Its tests are `scripts/dev-stack.test.mjs`, which `pnpm test:scripts` already picks up. Root script: `"dev:sitl": "node scripts/dev-stack.mjs"`.
- **The table, exactly** (spec § Services). All three start at once.
  - `sitl`: `tools/sitl/run_sitl.sh --non-interactive --streamrate 25`. Ports TCP 5760, 8088 and UDP 14551. Up when mavlink2rest has a `HEARTBEAT` from vehicle 1, within 60 s.
  - `mediamtx`: `tools/mediamtx/run.sh`. Ports TCP 8554, 8889 and UDP 8000, 8001, 8189. Up when TCP 8889 accepts, within 10 s.
  - `gcscode`: the shell's `dev` script with `--port 5173 --strictPort`. Port TCP 5173. Up when TCP 5173 accepts, within 30 s.
- **Paths come from the launcher file, not the working directory.** The scripts and the dev server belong to the checkout `scripts/dev-stack.mjs` is in. `SITL_MODEL`, `GCSCODE_SITL_HOME` and `GCSCODE_MEDIAMTX_HOME` pass through in the inherited environment.
- **Timings:**
  - poll each service's up check every 250 ms;
  - poll readiness every 1000 ms;
  - warn after 120000 ms;
  - treat signals within 1000 ms of the stop's start as the same Ctrl-C;
  - SIGKILL after a 5000 ms grace.

  All of them are overridable through `runStack({ timings })` for the tests.

- **Ready to fly**, both on vehicle 1, component 1: `SYS_STATUS.onboard_control_sensors_health` has `MAV_SYS_STATUS_PREARM_CHECK`, and `EKF_STATUS_REPORT.flags` has `EKF_POS_HORIZ_ABS`. mavlink2rest 1.0.2 renders both fields as names joined by `|`.
- **Never kill by name or pattern.** Only `process.kill(-pid, …)` on a PID the launcher recorded at spawn. The port check kills nothing.
- **Hands off the vehicle.** The launcher only sends `GET` to mavlink2rest. It never arms, changes mode or sets a parameter.
- **Writes no files, runs no setup.** It never downloads or builds anything.
- **Exact text:**
  - `ready to fly`;
  - `pnpm --filter sitl run setup` in `run_sitl.sh`'s three messages;
  - `pnpm fly-sitl --circle 3` as the next step.
- **Tests:**
  - They never start SITL, MediaMTX or Vite. They use only ephemeral ports (bind port 0), never the stack's fixed ones.
  - Every process a test starts is stopped by its PID in a `finally` or an `after`.
  - Every new test is seen failing before it passes. Each task's report lists the mutations it ran and any that survived (`CLAUDE.md` § Tests).
- **Worktree discipline.** Every command is prefixed `cd <worktree> &&`. Run `git branch --show-current` before every commit; if it says `master`, stop. Run `pnpm format`, `pnpm test`, `pnpm check` and `pnpm lint` only with that prefix.

## Decisions this plan adds

The spec leaves these open; each is my call. Facts marked _measured_ were checked on this Mac on 2026-11-10.

1. **The UDP check binds `::` with `ipv6Only: false` and `0.0.0.0`.** A port is in use when either bind fails with `EADDRINUSE`; other bind errors are ignored. _Measured:_ a dual-stack `::` bind failed against holders on `127.0.0.1` (the owner's mavlink2rest on 14551), on `[::]` (the owner's MediaMTX on 8000) and on `::1` only. A `0.0.0.0` bind missed the `::1`-only holder. `0.0.0.0` stays as the fallback for a machine without IPv6.
2. **The TCP check connects to 127.0.0.1 and ::1, with a 1000 ms timeout each.** The port is in use when either connects. _Measured:_ the owner's arducopter and mavlink2rest answer on 127.0.0.1 only, and MediaMTX answers on both.
3. **Naming the holder.** The check runs `lsof -nP -Fpcn` with `-iTCP:<port> -sTCP:LISTEN`, or `-iUDP:<port>`, and a 2000 ms timeout. For UDP it keeps only entries whose local address, the part before any `->`, ends in `:<port>`. It names each holder once as `<command>, PID <pid>`. If lsof fails or finds nothing, the line names no holder.
4. **gcscode runs as `pnpm --silent --filter @gcscode/shell dev --port 5173 --strictPort`,** with `pnpm` from `PATH`. _Measured:_ the flags reach Vite. Without `--silent`, every stop printed pnpm's `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL … Command failed with signal "SIGTERM"`. With it, Vite's own output and errors still show.
5. **Exit codes:** 0 after a stop asked for by a signal, 1 after any failure (ports in use, failed launch, a service exiting). _Measured:_ under pnpm, exit 130 prints `ELIFECYCLE Command failed with exit code 130.` after every clean Ctrl-C, and exit 0 prints nothing. pnpm waits for the script to exit, and the two SIGINTs arrived within 1 ms of each other.
6. **Output.**

- Each service line is prefixed with the service's name padded to the longest name, then `| ` (`sitl     | `), as `docker compose up` does. Service stdout goes to stdout and stderr to stderr.
- The launcher's own lines start with `==> ` and have no prefix; continuation lines are indented four spaces.
- A partial last line is printed when its stream ends.

7. **Last lines:** the launcher keeps each service's last 20 lines in memory. On a failure it prints them for every service that exited by itself or missed its deadline, under `==> Last lines from <name>:`.
8. **The signal window counts from the start of the stop, whatever started it.** A signal more than 1000 ms after that skips the grace.
9. **Safety net:** a `process.on('exit')` hook sends SIGKILL to every group not yet seen gone. An uncaught error in the launcher then takes its services down with it. A SIGKILL to the launcher still leaves them running, as the spec says.
10. **Readiness reads.** It reads `GET <mavlink2rest>/v1/mavlink/vehicles/1/components/1/messages/<NAME>`. _Measured:_ for a message not seen yet, mavlink2rest answers 200 with the body `None`. That body, any non-JSON body and any network error all count as "not seen yet". Flag fields are split on `|` and trimmed, then compared whole: `EKF_PRED_POS_HORIZ_ABS` is not `EKF_POS_HORIZ_ABS`.
11. **The 120 s count starts when readiness polling starts,** once every service is up. Polling stops after "ready to fly" is printed.
12. **Addresses live in the table.** Each entry carries its `addresses`, which the "ready to fly" banner prints in table order, so camera-sim adds its own when it joins. The values are gcscode's own defaults:

- `ws://localhost:8088/v1/ws/mavlink` from `extension-mavlink`;
- `http://localhost:8889/drone-1/whep` from `extension-video`.

13. **Docs beyond Delivery 2's list.**

- `tools/sitl/README.md` and `tools/mediamtx/README.md` each get one sentence pointing at `pnpm dev:sitl`.
- In `tools/sitl/README.md`, "The launcher stops if 5760 or 8088 is already taken" becomes "`run_sitl.sh` stops …", because "the launcher" now means `dev-stack.mjs`.
- The roadmap entry is ticked as shipped.

## Review focus

The spec implies these but no test in its text exercises them. Each is pinned by a test in the task named.

1. **A message mavlink2rest hasn't seen.** The `200 None` body means "not yet". It must not throw, and it must not stop the stack (Task 3).
2. **A look-alike flag.** `EKF_PRED_POS_HORIZ_ABS` set without `EKF_POS_HORIZ_ABS` is not a position (Task 3).
3. **A port held only on IPv6.** On this Mac a Vite on `localhost` listens on `::1`. The TCP check must see a `::1`-only listener, and the UDP check a `::1`-only socket (Task 2).
4. **A group that outlives its leader.** `run_sitl.sh`'s arducopter and mavlink2rest, and pnpm's Vite, are grandchildren. Stopping must reach them, including when the leader has already exited (Task 1).
5. **A command that cannot start.** With `pnpm` not on `PATH`, spawn emits `error`, not `exit`. It must be a failed launch that names the service and stops the others, not a crash that leaves them running (Task 1).

### Task 1: run and stop

`runStack()` with stub services: start, prefix, wait for up, fail, and stop.

**Files:** create `scripts/dev-stack.mjs` and `scripts/dev-stack.test.mjs`.

**Interfaces (produces):**

```js
/** @typedef {{ proto: 'tcp' | 'udp', port: number }} Port */
/** @typedef {{
 *   name: string, command: string, args: string[], cwd: string,
 *   ports: Port[],                    // used from Task 2
 *   up: () => Promise<boolean>,       // a throw counts as false
 *   upWithinMs: number,
 *   addresses: [label: string, url: string][],  // used from Task 3
 * }} Service */
export const TIMINGS; // { upPollMs: 250, readyPollMs: 1000, readyWarnMs: 120000, signalWindowMs: 1000, killGraceMs: 5000 }
/** Resolves to the exit code. */
export async function runStack({ services, mavlink2rest, timings }); // timings merge over TIMINGS; mavlink2rest is unused until Task 3
```

Behaviour:

- **Signal handlers first.** `runStack` installs its SIGINT, SIGTERM and SIGHUP handlers before doing anything else.
- **Start.** It prints `==> Starting <names, comma-separated>`, then spawns every service at once with `spawn(command, args, { cwd, detached: true, stdio: ['ignore', 'pipe', 'pipe'] })`. `detached` gives each service its own session and process group, with no terminal.
- **Up.** Each service's `up()` is polled every `upPollMs` until it returns true; then `==> <name> is up (<s> s)` prints, with the seconds since launch to one decimal place. Once every service is up, `==> All up.` prints. A service not up within its `upWithinMs` is a failure: `==> <name> was not up within <s> s.`
- **Exits.** A service exiting while the launcher is not stopping is a failure. The message is `==> <name> exited with code <n>.` or `==> <name> was stopped by <SIGNAL>.`, with ` during startup` before the full stop when it happens before "All up". A spawn `error` is a failure too: `==> <name> could not start: <error.message>`.
- **Failure.** Stop everything, print the last lines (decision 7), and resolve 1.
- **Signals.** The first signal stops everything and resolves 0. A later signal more than `signalWindowMs` after the stop began sends SIGKILL to every group still alive at once. Any other signal is ignored.
- **Stop.** It is idempotent. It prints `==> Stopping <names>`, then sends SIGTERM to `-pid` of every spawned service, the exited ones included, and ignores ESRCH. It checks `process.kill(-pid, 0)` every 100 ms until each group is gone (ESRCH).
  - A group still alive after `killGraceMs` gets SIGKILL, with `==> <name> did not stop within <s> s; killed it.`
  - It waits for every child's `close`, so the output is flushed, then prints `==> Stopped.`
- **Safety net** (decision 9).

Test harness, in the test file:

- `launch(script, env)` writes nothing to disk. It spawns `process.execPath` with `['--input-type=module', '-e', script]`, `detached: true` (its own group, as a terminal's foreground job is), and collects stdout and stderr. It returns `{ child, out(), err(), exited }`.
- The script imports `runStack` by the file URL of `dev-stack.mjs`, builds stub services, and calls `process.exit(await runStack(...))`.
- Stubs are `process.execPath -e <code>` services. Behaviour comes from arguments: print lines, exit with a code after N ms, ignore SIGTERM, take N ms to exit on SIGTERM, start a grandchild and print its PID, record every signal received into a file in a temp folder.
- A terminal's Ctrl-C is `process.kill(-child.pid, 'SIGINT')`. pnpm's doubled one is two of those, 20 ms apart.

- [ ] **Step 1: Write the failing tests.** Each test sets short timings, for example `killGraceMs: 1500`, `signalWindowMs: 300`, `upPollMs: 50`, and has a `{ timeout: 20000 }`.
  - `it prefixes each service's lines with its padded name, stdout to stdout and stderr to stderr`. Services `a` and `bbb`; expect `a   | hello` on stdout and `bbb | oops` on stderr. A last line without a newline is still printed.
  - `it starts every service before any is up`. Each stub writes a marker file. Service `a`'s `up()` waits for `b`'s marker and `b`'s waits for `a`'s. Expect `==> All up.`
  - `one Ctrl-C stops every service and its grandchildren, and exits 0`. Expect exit code 0, `==> Stopped.`, and the grandchild PID gone (`process.kill(pid, 0)` throws `ESRCH`).
  - `the terminal's Ctrl-C reaches the launcher, not the services`. After a group SIGINT, the stub's signal file holds `SIGTERM` and never `SIGINT`.
  - `two Ctrl-Cs within the window count as one`. The stub takes 800 ms to exit on SIGTERM and writes `graceful` when it does; `killGraceMs` is 3000. Send two SIGINTs 20 ms apart: expect `graceful` and no `killed it`.
  - `a Ctrl-C after the window skips the grace`. The stub ignores SIGTERM; `killGraceMs` is 10000. Send a SIGINT, then another at 800 ms. Expect the launcher to exit within 3000 ms of the first, and the stub gone.
  - `a service that ignores SIGTERM is killed after the grace`. With `killGraceMs` 1000: expect `did not stop within 1 s; killed it` and the stub gone.
  - `SIGTERM and SIGHUP stop it like Ctrl-C`. One test per signal, sent to the launcher's PID only. Expect exit 0 and the stubs gone.
  - `a service that exits during startup fails the launch`.
    - Stub `bad` writes `ERROR: venv missing. Create it with:  pnpm --filter sitl run setup` to stderr and exits 1. Stub `good` runs forever.
    - Expect exit 1, `bad exited with code 1 during startup`, and `==> Last lines from bad:` followed by the ERROR line, printed after `==> Stopped.`
    - `good`'s group is gone.
  - `a service not up by its deadline fails the launch`. `up()` is always false, with `upWithinMs` 500: expect exit 1, `was not up within 0.5 s`, and the others stopped.
  - `a service that exits after startup stops the stack`. It exits 0 at 700 ms, after `==> All up.`: expect exit 1, `exited with code 0.` and the others' groups gone.
  - `a command that cannot be spawned fails the launch`. The command is a path that doesn't exist: expect exit 1, `could not start`, and the other stub gone.
  - `the group is stopped even when its leader has already exited`. The stub starts a grandchild, prints its PID, then exits 1 at once. Expect the grandchild gone after the failed launch.

### Task 3: ready to fly, and the docs

**Files:**

- Modify: `scripts/dev-stack.mjs`, `scripts/dev-stack.test.mjs`
- Docs: `CLAUDE.md` (Commands), `README.md` (Running it), `tools/sitl/README.md`, `tools/mediamtx/README.md` and `docs/roadmap.md`

**Interfaces:**

- Consumes `runStack`, `MAVLINK2REST` and the `addresses` from Tasks 1 and 2.
- Produces:

```js
/** mavlink2rest's message object, or undefined (decision 10). */
export async function fetchMessage(baseUrl, name);
/** Pure. Either argument may be undefined. */
export function readiness(sysStatus, ekfStatus); // { prearm: boolean, position: boolean }
```

After `==> All up.`, `runStack` prints `==> Waiting until the vehicle is ready to fly.` It then polls `SYS_STATUS` and `EKF_STATUS_REPORT` every `readyPollMs`. When both are true, it prints the banner below once and stops polling. The addresses come from each service's `addresses`, in table order, with labels padded to the longest:

```
==> ready to fly (<s> s)
    MAVLink WebSocket  ws://localhost:8088/v1/ws/mavlink
    WHEP               http://localhost:8889/drone-1/whep
    RTSP               rtsp://localhost:8554/drone-1
    gcscode            http://localhost:5173/
    Fly it from another terminal:  pnpm fly-sitl --circle 3
    Ctrl-C stops everything.
```

If one or both are still false `readyWarnMs` after polling began, it prints the matching line or lines once and keeps polling. `<n>` is `readyWarnMs` in whole seconds.

```
==> Not ready to fly after <n> s: the pre-arm checks still fail; MAVProxy's PreArm lines above say why. Still waiting.
==> Not ready to fly after <n> s: no position yet; the EKF is not using GPS (no "EKF3 IMU0 is using GPS" line above). Still waiting.
```

## Deferred from review

Findings from PR #53's reviews that this PR does not fix, each with why and what brings it back.

- **A dead mavlink2rest after "All up" reads as "not ready".** The 120 s warning then blames the pre-arm checks or GPS, not the link. `run_sitl.sh` keeps running when mavlink2rest dies, and its output goes to `/tmp/mavlink2rest.log`. Revisit when someone meets the warning with mavlink2rest gone, or with the next change to the readiness poll.
- **arducopter or mavlink2rest dying after startup goes unnoticed.** `run_sitl.sh` keeps running while MAVProxy retries the link, so `sitl` never exits. That is `run_sitl.sh`'s design, and the spec treats `sitl` as one service. arducopter did exit once in the owner's own SITL run on 2026-11-10, outside the launcher, cause unknown. Revisit when it happens under the launcher: make `run_sitl.sh` exit when arducopter or mavlink2rest exits.
- **Ctrl-\ (SIGQUIT) leaves the services running,** as a SIGKILL of the launcher does: the exit safety net does not run when a signal ends Node. The spec names Ctrl-C, SIGTERM and SIGHUP. Revisit if anyone finds services left running.
- **`run_sitl.sh`'s banner says to type `exit` at the MAVProxy prompt,** which the launcher does not give. Cosmetic. Revisit with the next change to `run_sitl.sh`'s output.
- **The entry point compares `process.argv[1]` with the module's real path,** so `node` run through a symlinked path exits 0 and prints nothing. `pnpm dev:sitl` passes the real path, and `scripts/lint-docs.mjs` and `.claude/scripts/check-dispositions.mjs` use the same guard. Revisit if anyone runs one of these scripts through a symlink: fix all three guards together.
- **Launcher branches no test pins:** a signal during the 250 ms failure gather (it stops at once and exits 1), `groupExists` reading EPERM as "still there", and waiting for `close` before `Stopped.` when the stop is prompt. Each was read by its reviewers. Revisit with the next change to the stop sequence.
- **Real-timer windows in `scripts/dev-stack.test.mjs`** (300 ms to 2 s) may be tight on a loaded machine. Revisit at the first flaky run.
